# Users Module

## Overview
This module handles the core identity, authentication, and role-based access control (RBAC) for the Real Estate Platform.

## Key Architectural Decisions
- **Custom User Model**: Bypasses Django's default `auth_user`. Uses `email` as the primary `USERNAME_FIELD` instead of a username.
- **Audit Trails**: Inherits from `TimeStampedModel` for automated `created_at` and `updated_at` tracking.
- **Soft Deletion**: Inherits from `SoftDeleteModel`. Users are never hard-deleted from the database to preserve historical listing data; they are flagged via `is_deleted` and `deleted_at`.
- **Role Flags**: Uses simple boolean flags (`is_owner`, `is_agent`, `is_staff`) instead of complex group tables to minimize database joins during authorization checks.

## GraphQL APIs
- `Query.users`: Fetches a list of all users. Exposes basic profile data and roles.
- **Security Note**: Password hashes and administrative flags (`is_superuser`, `is_staff`) are strictly omitted from the `UserType` GraphQL node.

## Test Scenarios Covered
- **Model Tests**: 
  - `UserManager` successfully creates standard users and superusers with correct flags.
  - Email validation (rejects empty emails).
  - Soft-delete functionality correctly flags the user and sets the deletion timestamp without dropping the row.
- **API Tests**: 
  - Validates that the GraphQL `users` query returns expected data structure.
  - Ensures dummy data generated by `factory_boy` is accurately serialized.
